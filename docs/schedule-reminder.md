# 对话式定时闹铃与提醒

## 需求与数据约束

设备最多保存 16 项任务，任务类型为闹铃（`alarm`）或普通提醒（`reminder`），重复方式为单次、每天、工作日、周末或每周指定星期。标签必须是有效 UTF-8、长度为 1–80 个 Unicode 码点且去除 Unicode 空白后非空；设备保留原始标签中的边缘空白。创建时必须在绝对本地时间和相对秒数之间二选一；相对秒数只适用于单次任务。每周任务的星期使用 1–7 表示周一至周日。

任务与递增 `next_id` 组成同一份 JSON，并按每片最多 1800 字节保存在 NVS `schedule` 命名空间：`chunks` 记录分片数，`data0` 至 `dataN` 按序保存 JSON 分片。系统时间尚未同步时，不触发、不删除、不推进任何任务。重启后的首次有效时间检查中，单次任务逾期不超过 5 分钟会补响，超过 5 分钟会删除并写入日志及 `schedule/last_missed`；重复任务不补响，直接推进到未来下一次并持久化。

若任务 JSON 或分片损坏，启动过程会输出明确错误日志，把原因写入 `last_load_error`，清除损坏分片并以空任务集继续启动。触发时刻使用本地墙钟判断；闹铃 10 分钟和提醒页 60 秒的持续上限使用单调时钟，不受校时影响。

创建重复任务时，首次 `trigger_at` 必须已经符合重复规则：工作日只能为周一至周五，周末只能为周六或周日，每周任务的首次星期必须包含在 `weekdays` 中；不匹配时明确返回参数错误，不自动改期。

查询与清空均支持 `kind=all/alarm/reminder`，默认 `all`，分别表示全部任务、仅闹铃、仅普通提醒。

同批到期任务先按原触发时间排序，同一时刻闹铃优先，再按 id 递增。任务在产生一次到期事件时即删除或推进并持久化，避免每秒重复触发。

## 触发行为

触发会中断当前服务端播报和本地音乐，清空解码与播放队列、网易云歌词时间线及歌词页面，且停止后不恢复音乐。若当前输出音量低于 80%，触发期间只在运行内存与硬件上临时提升到 80%，不写 NVS；结束时仅在用户没有主动调节音量的情况下恢复原音量。

- 闹铃循环播放本地提示音，直到停止、稍后提醒或达到 10 分钟上限。
- 普通提醒连续播放两次本地提示音，页面保留最多 60 秒。设备必须等待两次提示音全部从扬声器播放完成后，才向服务端发送 `notifications/schedule/triggered`，避免服务端 TTS 切换播报状态时截断提示音。在线时由服务端按 `speak=true` 播报“提醒你：内容”；该提醒的 TTS 完成后，设备自动进入默认收听模式。设备发送通知后最多等待 15 秒让服务端开始 TTS，超时则解除交付占用并恢复临时音量，避免离线状态阻塞后续任务或误关联普通对话的 TTS；离线时仍保留两次本地提示音和屏幕文字。
- 触发页显示类型、时间、内容和“按键停止 / 可语音稍后提醒”。Waveshare ESP32-S3 Touch AMOLED 1.32 的 BOOT 短按在页面活动时优先停止；板级代码只调用通用 `Application` 接口。
- 稍后提醒生成新的单次任务，默认 5 分钟，允许 1–60 分钟。重复任务原有下一次计划不受影响。

## 验证范围

主机测试覆盖容量上限、五种重复、跨天、重启恢复与补响、到期去重、删除、清空、停止、稍后提醒，以及“提示音完成→提醒 TTS→自动收听”的交付状态机。真机仍需验证 NVS 掉电恢复、系统时间同步、提示音循环时长、80% 临时音量、服务端 TTS、TTS 后拾音、WebSocket/MQTT 网络切换、圆屏布局和 BOOT 实体按键。
